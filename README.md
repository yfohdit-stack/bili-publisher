# B站投稿台

一个跑在自己电脑上的 B站投稿面板。浏览器里拖视频、填标题分区、排进队列，软件按**单线程顺序**帮你投出去。

> 当前版本：**v102**（见 `app/server.py` 中的 `APP_VERSION`）。
> 仅用于个人本地投稿，凭据只存在本机，不上传任何地方。

## 功能

- **队列投稿**：多文件排队，一个一个传，失败自动重试，进度和日志都看得见
- **24 小时额度把关 + 封禁保护**：投稿前先数一遍这个账号最近 24 小时发了多少稿，超过上限会拦截并等待；命中 B站「n+1 封禁」时自动暂停到额度归零再续投（默认上限 50，可改）
- **两条上传通道**：优先复用本机 `biliup`，没有就回退到内置的 B站官方接口
- **多分P**：多个视频合成一个稿件的 P1/P2…
- **多账号**：可登记多个 B站账号，按任务指定投放账号，额度/节流/风控按账号隔离
- **定时发布**：距现在 4.5 小时以上交给 B站定时，不足则在本地等到点再投
- **封面**：可用自己的图，也可从视频自动抽一帧
- **模板**：把分区、标签、简介存成模板，下次一键套用
- **扫码登录**：B站 APP 扫码，Cookie 自动写入本机

## 快速开始

需要 **Python 3.9 及以上**，且系统装有 `ffmpeg` / `ffprobe`（封面抽帧依赖）。

```bash
# macOS / Linux
bash start.sh

# Windows
start.bat
```

首次运行会建虚拟环境并装依赖（flask、bilibili-api-python 等），然后自动打开 http://127.0.0.1:5277/

也可以手动：

```bash
pip install -r requirements.txt
python run.py
```

常用参数：`--port 5277` 换端口，`--host 0.0.0.0` 让局域网其他设备也能访问，`--no-browser` 不自动开浏览器。

## 第一次使用：登录

推荐扫码：打开设置面板 → 「用 B站 APP 扫码登录」 → 用 B站 APP 扫屏幕上的二维码并点确认，Cookie 会自动写入。

同一部手机无法扫描自己的屏幕，这时点「保存二维码图片」，再打开 B站 APP → 扫一扫 → 右上角「相册」，选中刚保存的图即可。

也可以手工粘贴 Cookie（需在电脑浏览器登录 bilibili.com 后复制）：

- 整段请求头：`SESSDATA=xxx; bili_jct=xxx; buvid3=xxx; DedeUserID=xxx`
- 或分别填 `SESSDATA`、`bili_jct`、`buvid3`、`DedeUserID`

点「保存并校验」，账号名和近 24 小时投稿数会出现在顶栏。

> Cookie 只存在本机的 `data/config.json`（权限 0600），不会上传到任何地方。`SESSDATA` 等同于账号登录态，**别发截图、别提交到代码仓库**（仓库已通过 `.gitignore` 忽略 `data/`）。

## 两条上传通道

| 通道 | 前置条件 | 说明 |
| --- | --- | --- |
| biliup | 本机装了 `biliup`，并且已经 `biliup login` 过（存在 `cookies.json`） | 上传链路经过大量实战验证，大文件更稳 |
| 内置官方接口 | 只要登录了网页 Cookie | 自己实现预上传、分块、合并、提交，无需额外软件 |

默认 `自动`：biliup 有登录态就用 biliup，否则用官方接口。设置里可以固定其中一条。带话题 / 仅自己可见的稿件会强制走官方接口（biliup CLI 不支持）。

> biliup 1.2.x 的登录态是它自己生成的 `cookies.json`（内含 app access_token），**不是网页 Cookie**，没法由 SESSDATA 伪造。所以要用这条通道，请先在终端执行一次 `biliup login`，再把登录文件路径填到设置里。

## 24 小时额度与封禁规则

投稿任务真正开始前，会调用创作者中心稿件列表接口，把投稿时间落在最近 24 小时内的稿件数出来（已发布 + 审核中 + 未通过），再结合本机投稿账本（`ledger.py`）去重合并：

- 数量 < 上限 → 正常投稿
- 数量 == 上限（刚好满 n）→ 暂停排队，等最早一篇滑出腾出空位后自动续投
- 数量 > 上限（达到 **n+1**）→ **触发 B站 24h 投稿封禁**：封禁期内即使老稿陆续滑出、额度降到 n 以下也**不能投**，必须等窗口内的稿件全部过期、额度**归 0** 才恢复。程序会自动暂停到解封时刻再续投，无需人工值守
- 统计没抓全（接口超时、或只能退回「仅已发布」口径）→ 默认按保守策略拦下并暂停队列，不拿一个偏小的数字放行

上限在设置里改（默认 50）。统计不全时的保守行为由「额度严格模式」控制（默认开）：关掉后只在界面提示、照常投稿。统计结果在顶栏常驻显示，点一下可强制重算。

设置 →「额度与重试」→ **额度恢复后自动继续投稿**（`auto_resume`，默认开）：开启后只会自动解除部署/升级时的保护性暂停（`boot`）和额度封禁等待（`quota`），**不会**悄悄解除你主动按下的暂停（`manual`）或连续限流等待（`rate`）。

## 定时发布怎么走

| 距发布时间的间隔 | 行为 |
| --- | --- |
| ≥ 4 小时 30 分 | 现在上传，把发布时间交给 B站定时队列（B站要求定时至少提前 4 小时，这里多留 30 分钟余量） |
| 提前量 ~ 4 小时 30 分 | 任务挂「等待定时」本地等；按文件体积估算上传耗时（保守 2MB/s，结果夹在 5~60 分钟），提前这么久开始传 |
| < 提前量 | 立即上传，投出去就是现在 |
| > 15 天 | 直接失败（B站定时上限 15 天） |

本地等待的定时稿没法精确到秒：实际发出时间与预定相差超过 2 分钟时，任务消息会写明早了/晚了多少。要分秒不差，就把时间设到 4 小时 30 分以后交给 B站定时。

## 上传前的检查

排队之前先过一遍本地校验，不合法的请求一个字节都不落盘：

- 扩展名必须是视频（mp4 / flv / mkv / mov / avi / webm / ts / m4v / wmv），封面必须是图片（jpg / jpeg / png / webp / bmp）
- 单文件体积上限（默认 8192 MB）、单稿件分P 数量上限（默认 20），都在设置里改
- 磁盘余量：本次上传体积 + 512 MB 保留，不够直接拒绝，不把盘写满
- 落盘后按实际大小再复核一次，超限的文件当场删掉，不留半成品

## 10 分钟节流

最近 10 分钟内最多放行 10 个视频，按账号独立计算（A 占满窗口不拖 B）。多分P 稿件占多个名额，窗口腾不下就等最老的记录滑出去。等待原因和剩余时间写在任务消息里，精确到分钟。

## 常见问题

**顶栏显示未登录 / 额度是「—」**
Cookie 过期或粘错了。重新登录 B站复制一次，设置里保存并校验。

**任务是「已拦截」/ 红色封禁横幅**
近 24 小时投稿数已经到 n+1，触发 B站 24h 封禁。封禁期内额度下降也不能投，必须等窗口内稿件全部过期、额度归零。横幅会显示解封倒计时，到点自动续投，无需人工。

**任务是「已中断」**
上次运行时程序被关掉了（Ctrl+C、断电、kill），上传没跑完。稿件有可能已经发出去了：先去创作中心核对，确认没有重复稿件再点「核对后重投」。程序不会自动重投，就是为了避免重复稿件。

**额度明明没满却被拦下，提示「额度统计不完整」**
创作者中心的稿件列表没抓全，数字偏小不可信，严格模式会保守拦下。点「刷新额度」重试；确认要按偏小的数字放行，就在设置里关掉「额度严格模式」。

**换封面失败 / 没有可用封面**
封面靠 ffmpeg 抽帧，先确认 `ffmpeg`、`ffprobe` 在 PATH 里（`ffmpeg -version`）。

**biliup 报 `credential validation failed`**
登录文件过期，终端里重新 `biliup login`。

**端口被占**
`python run.py --port 5288`。

**能同时跑几个任务？**
一次只跑一个。B站对同账号并发上传不友好，顺序执行也保证额度统计不会打架。

## 已知限制

- 队列是单线程顺序上传，没做并发
- 官方接口通道依赖 `bilibili-api-python`，B站接口变动时可能要跟着升级
- 定时发布能不能用，取决于账号是否具备 B站定时发布权限
- 只处理本机文件上传，不做远端拉取、不做转码
